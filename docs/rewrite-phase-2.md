# ApkStart 重构 · 第二阶段

## 在 Windows 录音和播放

1. 在 Windows「设置 → 系统 → 声音」选择默认输入（麦克风）和输出（耳机或扬声器）。如果输入仍不可用，检查「隐私和安全性 → 麦克风」是否允许桌面应用访问。
2. 在 ApkStart「设置 → 性能与资源」开启「Windows 麦克风输入」，停止并重新启动安卓运行时。开关默认关闭；关闭时也要停止或重启已经运行的实例。安卓声音输出是另一个开关。
3. 在目标安卓 App（如全民 K 歌）开始录音时，按需在安卓权限弹窗允许麦克风。已授过权的应用可能不再弹窗；可在安卓设置中单独撤销。ApkStart 安装或缓存恢复不会批量授权。

这是 [Android Emulator 的主机音频接口](https://developer.android.com/studio/releases/emulator)，不是整块 USB 设备直通。Android 不会获得耳机或麦克风的 Windows 设备 ID；不提供低延迟监听、单应用输入选择或新的键鼠/手柄直通。驱动不能代替用户启用主机采集。修改音频配置会跳过不匹配的快速启动快照，不清除用户数据。

## 稳定性、兼容性和 I/O

- 接管/停止须检查 ApkStart AVD 的锁、监听者 PID 以及控制台 AVD 名称。遇到归属不明的实例不会按端口猜测目标或扫描并结束模拟器进程。重新启动失败会返回实际错误。清理缓存前核实运行时已退出；预览不关机，清理不删除 AVD 锁。ADB 强制走本机配置的端口，不用进程名清理其他模拟器或强制重启占用端口的 ADB。Windows 调优只改已核验的 PID，不再拉起 PowerShell 枚举进程。
- 拆分包在各自的暂存目录流式展开，优先读取 `base.apk` 的应用身份但不改变安装顺序。磁盘检查失败时不解包；准备完成后复查实际写入字节和可用空间。ABI 重试复用这一份解包结果。
- 解包、准备或安装失败均释放暂存文件；原包备份失败会提示无法自动恢复，不写入无效路径。未把 Android 安装与本机清单记录做成可跨进程回滚的事务。
