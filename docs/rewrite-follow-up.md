# ApkStart：边界收口与诊断

基线 `81d5a779b0e1f08a0c86bc117b5bd1f19681e477`。本轮按审查问题逐项处理，不改变已发布的 IPC 通道名，也不更改 APK 安装和窗口模式的产品入口。

| 项目 | 新边界 |
|---|---|
| IPC 诊断 | 统一记录异常发生的通道、分类和可用的项目内调用位置。保留旧的返回结构，已被转换成返回值的异常通过同一入口记录。用户取消或明确业务拒绝不算异常；新的 IPC 日志不写请求参数、底层命令输出或绝对堆栈路径。 |
| ADB | ADB 程序选择、端口环境和命令传输由共享客户端负责；ADB server 控制与需要设备的命令仍分开。使用已验证的模拟器目标和实例代际检查，避免旧客户端和旧联网结果跨实例复用。 |
| 资源设置 | 正在写入的内存、CPU、数据分区设置在原子保存前统一检查。保持 `0` 为自动，不改写未提交的旧字段；实际扩容仍需独立核实磁盘余量。 |
| 主进程 | 按启动装配、后台工作、窗口呈现和启动策略划分边界。应用启动仍受操作队列、受管实例与窗口会话约束。 |
| 渲染层 | 设置导航、资源/运行时、显示/输入、存储/集成、诊断、体检和更新各有模块；保留原生 Electron preload 和传统脚本。每个按钮的监听属于一个模块，修复了两个重建快捷方式入口重复触发或无响应和关机失败却报成功的问题。 |
| 残留扫描 | 注册表查询和文件盘点不再同步堵住主进程；文件查询分批并行，当前安装、数据和 AVD 仍受保护。清理确认和执行未混入只读扫描。 |
| 接口收口 | 网络体检只通过 Runtime 接口。为兼容现有 preload，`app:clearOrphans` 等旧通道名不改。 |

验证包括可重复的 IPC 故障和脱敏测试、ADB 路由夹具、设置写入回归、合成启动/接窗、残留扫描及真实 Electron 设置页。合成基准仅用于确认扫描期间事件循环可以继续服务，不代表所有磁盘或注册表的实际耗时。在此轮不接入真实安卓、录音设备，不测试实机帧率，也不实施无需重启的快速旋转。
